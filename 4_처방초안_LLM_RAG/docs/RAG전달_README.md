# AKI 처방 변경 초안: RAG 검증용 전달 자료

작성: 김우주 (AI 파트) · 2026-10-14

RAG 검증을 맡아 주셔서 감사합니다. 이 폴더에는 처방 초안 모델이 test 환자 600건에 대해 만든 처방 변경 초안과, 검증에 필요한 환자 상태 정보가 들어 있습니다. 아래에 파일 구성, 초안을 만든 방식, 검증 결과를 돌려받을 양식을 정리했습니다.

## 1. 데이터 취급 (먼저 읽어 주세요)

- 이 자료는 MIMIC-IV에서 만든 **환자 단위 자료**입니다. PhysioNet 자격을 가진 팀원만 열람하고, 팀 밖으로 공유하거나 재배포하지 않습니다.
- **외부 온라인 LLM 서비스(ChatGPT, Gemini, Claude 등)의 API나 웹에 환자 정보를 넣으면 안 됩니다.** PhysioNet 이용 약관에 어긋납니다. 검증은 연구실 서버의 로컬 LLM으로만 해 주세요.
- 압축 파일은 암호화되어 있고, 암호는 별도 메신저로 전달합니다.

## 2. 파일 구성

| 파일 | 내용 |
|---|---|
| `drafts.jsonl` | 사례마다 한 줄. 위험도, 환자 상태 요약, 투여 중인 약, 처방 변경 초안, 득표율 (검증의 기본 입력) |
| `drafts.csv` | 초안 항목을 한 줄씩 펼친 표. 엑셀로 훑어보기용 |
| `drug_vocab.json` | 대상 약 목록(약 34개)과 학습 데이터 정답에서의 등장 횟수 |
| `rag_result_template.csv` | 검증 결과를 돌려받을 양식 (5장 참고) |
| `README.md` | 이 문서 |

### `drafts.jsonl` 필드

| 필드 | 설명 |
|---|---|
| `case_id` | 사례 ID. `aki_risk-<hadm_id>-<판단 시각>` 형식 |
| `risk_tier` | AKI 위험 신호등: `red`(상위 5%), `yellow`(상위 15%), `green` |
| `risk_prob` | 이후 24시간 안 AKI 발생 확률 (보정된 값) |
| `risk_factors` | 위험을 올린 주요 요인 3개 (한국어 문장) |
| `patient_summary` | **처방 모델이 실제로 본 입력 그대로.** 나이·성별, 위험 예측, 크레아티닌 추이, 최근 검사, 활력징후, 투여 중인 약(용량·횟수 포함), 체중·eGFR·소변량·수액 |
| `active_aki_drugs` | 판단 시점에 투여 중이던 AKI 관련 약 |
| `draft` | 처방 변경 초안. `{"신규처방": [...], "감량": [...], "증량": [...], "중단": [...]}` |
| `vote_ratio` | 초안에 들어간 약의 득표율 (16번 답 중 그 약을 제안한 비율). 모델의 확신 정도 |
| `other_candidates` | 기준에 못 미쳐 초안에서 빠진 후보 약과 득표율. 검증 중 참고용 |

`draft`가 모두 빈 목록이면 "이 환자는 24시간 안에 AKI 관련 약을 바꿀 필요가 없다"는 판단입니다.

## 3. 초안을 만든 방식

**상황 설정.** ICU 입실 48시간째에 그때까지의 기록만 보고, 이후 24시간 동안의 AKI 관련 약 처방 변경을 제안합니다. 판단 시점 이후의 기록은 입력에 들어가지 않습니다.

**처방 변경 종류.**

- 신규처방: 판단 시점에 투여 중이 아닌 약을 새로 시작
- 중단: 투여 중인 약을 끊음
- 감량·증량: 투여 중인 약의 하루 용량(1회 용량 × 횟수)을 10% 이상 줄이거나 늘림

중단·감량·증량은 `active_aki_drugs`에 있는 약에 대해서만 나옵니다.

**모델.** Qwen3.8-27B를 QLoRA로 학습했습니다. 같은 환자에게 16번 답하게 하고, 약마다 제안된 비율(득표율)이 기준값 이상이면 초안에 넣었습니다. 기준값은 검증(val) 데이터에서 정했습니다: 신규처방 0.125, 감량 0.0625, 증량 0.25, 중단 0.3125.

**참고.** `risk_prob`, `risk_tier`, `risk_factors`는 1차 위험 모델(AUROC 0.748)의 값입니다. 이후 추세 특징을 넣어 개선한 모델(AUROC 0.769)은 아직 처방 초안 입력에 반영하지 않았습니다.

## 4. 현재 초안의 수준 (검증 설계 참고용)

정답은 "실제로 그 24시간 동안 의료진이 바꾼 처방"이고, 초안과 정답이 겹치는 정도를 F1로 봤습니다. 비교 기준은 "자주 쓰이는 약을 그대로 제안하는 단순 규칙"입니다.

| 변경 종류 | 처방 초안 | 단순 규칙 | 해석 |
|---|---|---|---|
| 전체 | 0.158 | 0.141 | 비슷한 수준 |
| 신규처방 | 0.179 | 0.167 | 단순 규칙 수준 |
| 중단 | 0.158 | 0.000 | 규칙으로는 못 하는 판단에서 신호가 있음 |
| 감량·증량 | - | - | 사례가 적어 판단 불가 |

즉 **신규처방 제안은 걸러야 할 것이 많고, 중단 제안은 상대적으로 믿을 만합니다.** RAG 검증이 특히 신규처방에서 근거 없는 제안을 얼마나 걸러 내는지가 핵심 관심사입니다.

정답은 이 묶음에 넣지 않았습니다. 검증하는 쪽이 정답을 모르는 상태여야 RAG의 효과를 공정하게 측정할 수 있기 때문입니다. 결과를 돌려주시면 제가 정답과 비교해 채점하겠습니다.

## 5. 검증 결과를 돌려받을 양식

`rag_result_template.csv` 형식으로, **초안 항목 하나당 한 줄** 작성해 주세요.

| 열 | 내용 |
|---|---|
| `case_id` | 사례 ID |
| `action`, `drug` | 검증한 초안 항목 (`drafts.csv`와 같은 값) |
| `verdict` | `accept`(유지), `reject`(삭제), `modify`(변경), `add`(초안에 없던 항목 추가) |
| `modified_action`, `modified_drug` | `modify`나 `add`일 때 바뀐 변경 종류와 약 |
| `reason` | 판단 이유 (짧게) |
| `evidence_source` | 근거 문서 ID나 출처 |

초안이 비어 있는 사례에서 추가할 항목이 있으면 `add`로 적어 주세요. 약 이름은 `drug_vocab.json`의 이름을 그대로 써 주시면 채점이 쉽습니다.

## 6. 평가 계획

돌려받은 결과로 다음을 비교할 예정입니다.

1. **RAG 전후 일치도**: 초안 그대로의 F1과 RAG 검증 후의 F1 (변경 종류별)
2. **걸러 낸 항목의 성격**: `reject`된 항목 중 실제로 정답이 아니었던 비율
3. **위험한 초안 비율**: 의료진이 "위험한 처방 초안" 기준을 정해 주시면, RAG 전후로 그 비율이 얼마나 줄었는지

## 7. 확인 부탁드릴 것

- 파일 형식(JSONL/CSV)과 필드가 RAG 파이프라인에 맞는지
- 약 이름 매칭에 RxNorm이나 ATC 코드가 필요한지 (필요하면 추가하겠습니다)
- 600건이 검증하기에 많으면 신호등별로 나눈 일부(예: 빨강·노랑 전부 + 초록 일부)로 줄일 수 있습니다
